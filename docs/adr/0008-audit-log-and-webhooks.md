# ADR-0008: 監査ログと Webhook は、変更と同じトランザクションで記録する

## Status
Accepted (2026-10-27)

## Context
誰が・いつ・何をしたかを残し、他のシステム(チャット、ほかのツール)に変更を知らせたい。ログだけが残って変更が失敗する、
または変更だけが残ってログが無い、という食い違いは避けたい。通知の失敗で、本体の操作を失敗させたくない。

## Decision
- 監査ログ(`audit_log` 表)は、変更と同じトランザクションに書く。変更が失敗(404・400・409・403)したときは、ログも残らない。読み取りは記録しない。
- 操作者は、トークンのロール(`viewer` / `editor` / `admin`)。個人の識別は、トークンが個人に紐づいていないため、できない。
- 閲覧は管理者だけ(`GET /audit-log`、絞り込みとページングつき)。
- Webhook は、コミットが成功したあとに、別スレッドで 1 回送る(ロールバックなら送らない)。本文に HMAC-SHA256 の署名(`X-PipeBoard-Signature`)を付ける。URL と秘密鍵(16 文字以上)は環境変数で、誤りは起動時に止める。
- 送信の失敗は、警告のログに出し、要求は成功のまま。

## Consequences
良い: 変更とログが食い違わない。通知が遅くても、操作は待たない。
悪い: Webhook は再送しない(プロセスが止まる、受け側が落ちていると、失われる)。確実な配送が要る場合は、送信待ちの表(アウトボックス)が要る。
