# ADR-0010: アップロード画像は、推測できない URL で認証なしに配信する

## Status
Accepted (2026-10-27)

## Context
バージョンの画像は、ブラウザの `<img>` で表示する。`<img>` は `Authorization` ヘッダを送れないため、`token` モードで認証を要求すると、画像だけが表示されない。
(配信の経路そのものが無く、画像が一度も表示されていない不具合も、同時に見つかった。)

## Decision
- `GET /uploads/{filename}` で配信する。ファイル名は、保存時に UUID4 で生成したもの(元のファイル名は使わない)。
- 受け付けるのは、UUID4 の形と、画像の拡張子(png / jpg / jpeg / webp)の組だけ。それ以外(パス区切り・`..`・他の拡張子)は 404。
- 応答に `X-Content-Type-Options: nosniff` と、長期のキャッシュを付ける。
- 認証は求めない(名前を知っていることが、権限の代わり)。

## Consequences
良い: 画像が `token` モードでも表示でき、経路は 1 つで、任意のファイルを読み出せない。
悪い: URL を知っている人は、認証なしで見られる。URL を共有する運用は、画像の公開と同じと考える。
      機密の画像を扱うなら、署名つきの期限つき URL への移行が必要(今後の課題)。
